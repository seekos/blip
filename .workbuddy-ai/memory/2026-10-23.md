## macscp：GPUI Kit SFTP 客户端从零落地

在 `/Users/zy/Ai/personal/macscp` 新建 Rust 项目，`cargo build` 与 `cargo test` 均通过（7 个测试），
GUI 实机启动验证过三种状态：连接页、工作区（双栏 + 传输队列）、新建目录对话框。

### 结构

- `src/main.rs` 开窗 + 注册 `gpui_kit::assets::AllAssets`
- `src/app.rs` 根实体 `ScpApp`（状态机 / 事件泵 / 布局）
- `src/sftp/{types,worker,session,transfer}.rs` 网络层，跑在 `macscp-sftp` 线程的 Tokio runtime 上
- `src/session/store.rs` Keychain + profiles.json
- `src/ui/{file_pane,transfer_panel}.rs` 虚拟化表格与传输队列

### gpui-kit 0.8 / gpui-component 0.8 踩坑记录（重要，复用价值高）

1. **图标**：`gpui_kit::component::IconName` 只有组件自用的少量图标；完整 Lucide 目录在
   `gpui_kit::assets::IconName`。必须 `gpui_kit::application().with_assets(gpui_kit::assets::AllAssets)`，
   否则所有图标渲染成空白（不报错）。
2. **`overflow_y_scroll` / `track_scroll` 在 `StatefulInteractiveElement` 上**，不是
   `InteractiveElement`：div 必须先 `.id(...)` 变成 `Stateful`。
3. **`.disabled()` 来自 `Disableable`，`.ghost()/.primary()/.danger()` 来自 `ButtonVariants`**，
   都要显式 `use ... as _`。
4. **`cx.listener(...)` 返回 `impl Fn(&E, &mut Window, &mut App)`**，正好能直接喂给
   `Button::on_click` / `BreadcrumbItem::on_click`（后者参数是 `&mut App` 而非 `&mut Context`）。
5. **Rust 2024 的 `impl Trait` 捕获全部生命周期**：`let header = self.render_header(cx);` 之后再
   `&mut cx` 会 E0500。渲染辅助函数统一返回 `AnyElement`。
6. **`TableDelegate` 必需方法**：`columns_count` / `rows_count` / `column` / `render_td`；
   `render_td` 返回 `impl IntoElement`，分支多时统一 `.into_any_element()`。
   双击行用 `TableEvent::DoubleClickedRow`（`cx.subscribe_in`）。
7. **不能在 `cx.new(...)` 构造根视图期间 `window.open_dialog`** —— 会 panic
   "component window state is missing"。对话框只能在窗口建立之后（按钮回调 / 延时任务）打开。
8. `Progress::value()` 取 0..100；`Resizable` 用 `v_resizable(id)` + `resizable_panel().size(px).size_range(a..b)`。

### 设计约束（用户明确要求，后续改动需保持）

- 严禁在 `render` / `Context` 里 `tokio::spawn`；网络 I/O 全部在独立线程的 Tokio runtime，
  `flume` 收发 `SftpCommand` / `SftpEvent`。
- 文件列表必须走 `TableState` 虚拟化，不得用 div 循环。
- 传输进度 100ms 节流。
- 业务代码不 `.unwrap()`，错误统一走 `SftpEvent::Error` → Toast / 内联错误。

### 待办

目录递归传输、known_hosts 校验、重命名 UI 入口（worker 侧已实现 `SftpCommand::Rename`）。

### 新踩到的坑（重要）

9. **`Entity::update` 是独占租约，重入会 panic**：`App::update_entity_erased` 里
   `entities.remove(entity_id)` 把实体临时摘走，再 `update`/`read` 同一个实体会
   `cannot update ... while it is already being updated`。
   由此定下硬规则：**子实体事件回调里只许改别的实体**。
   具体做法：`Toolbar` 点「连接」先切自己的 `Connecting` 再 `emit`；`FilePane::navigate`
   先 `begin_loading` 再 `emit`；`Workspace::go_live` 对远端面板只 `leave_mock`、不触发
   `Navigate`（否则在 Workspace 被借用时同步回调自己）。
10. `gpui_kit::Timer` 不存在；定时用 `cx.background_executor().timer(dur).await`。
11. `ResizablePanel` 没有 `flex()`，只有 `size()` / `size_range()` / `visible()` / `fixed()`；
    `ResizablePanelGroup` 是 `RenderOnce`，可以 `.into_any_element()`。
12. `EntityId` 组合只支持 `(&'static str, usize/u64/EntityId)`，`(&str, bool)` 编译不过。

## 第三轮：按规格重写 SFTP 网络层 + 进程内假服务器

按用户给的枚举规格对齐了 `src/sftp/{mod,types,worker}.rs`：
`SftpCommand::{Connect, ListDir, Download, Upload, Mkdir, Remove, Rename}`（+ Cancel /
Disconnect / Shutdown），`SftpEvent::{Connected, DirListed, TransferProgress,
TransferCompleted, Error}`（+ Disconnected / TransferStarted / Notice）。
`Error` 保留 `context: ErrorContext` 枚举而不是裸 `String`，因为 UI 要靠它区分

- `worker.rs`：`thread::Builder` 具名线程 + `new_multi_thread` runtime；`guard()` 给
  每条指令套 30s 超时；取消表改成 `Arc<Mutex<HashMap>>`，传输任务结束自己摘条目（原来会泄漏）。
- `session.rs`：新增 `discover_private_key()`（id_ed25519 → id_ecdsa → id_rsa → id_dsa），
  `AuthMethod::PrivateKey` 的 path 为空即自动查找；toolbar 私钥栏留空不再报错。
- 新增 `src/sftp/testserver.rs`（`#[cfg(test)]`）：russh 服务端 + `russh_sftp::server::run`
  的假 SFTP 服务器，虚拟树在 `/home/tester`，15 个测试里 5 个走真实握手。

### 新踩到的坑

13. **russh 0.64 的 `server::Handler` 是 RPITIT**（`-> impl Future`），但 impl 里写
    `async fn` 仍然兼容；`channel_open_session` 要拿 `ChannelOpenHandle` 并 `reply.accept().await`，
    不 accept 会自动拒绝。
14. **`russh::keys::PrivateKey::random` 需要 RNG**，rand 0.10 的 API 已经变成

15. **沙箱里 bash 的 `grep` 会静默返回空**（明明有匹配），必须用 Grep 工具查代码。

## 第六轮：`demo-server` 特性（没有真机也能点全链路）

用户要求验证 Finder 拖放，但本机没有辅助功能权限、无法脚本模拟拖拽。于是把假服务器
编进二进制，一条命令就能手工点完：

- `Cargo.toml` 加 `[features] demo-server = []`；`testserver` 的 gate 改成

- `src/demo.rs`：独立线程 + 自己的 Tokio runtime，`block_on` 里 `seed()` → `spawn()` →

  runtime 一退出 listener 就没了，不能像 worker 那样建完就返回）。
- `ScpApp::apply_demo_login` 填表单并直接 `workspace.connect`，**故意 `remember = false`**，
  别把假账号写进钥匙串。

  **关键：测试从不初始化它**，所以 `entries.len() == 5` 那条断言不受影响 ——
  改成「把 VFS 里所有键都列出来」就会让并行测试随机失败。

### 新踩到的坑

26. **`posix-rename@openssh.com` 在 russh-sftp 3.0.1 里根本调不到**：`SftpSession::features`
    是 `pub(crate)`，`Features` 里没有该标志，`extensions.rs` 只有 HARDLINK / FSYNC /
    STATVFS / EXPAND_PATH / LIMITS，`RawSftpSession` 也没有通用的 `SSH_FXP_EXTENDED`
    入口。所以「首选 POSIX 原子重命名」只能降级成：直接 `rename`（OpenSSH 的
    sftp-server 本身就是 `rename(2)`，目标存在也能覆盖）→ 失败再 `unlink` + `rename`。
    **只有确认目标存在时才 unlink**，否则权限/跨 FS 报错会误删原文件。
27. **`guard()` 要求 `Result<T, String>`**，而 `probe_upload` 返回 `anyhow::Result`，
    必须 `.map_err(|err| format!("{err:#}"))` 包一层。
28. **`.filepart` 半成品必须写在临时文件路径上**：`upload_resumes_from_partial_filepart`
    一开始把半成品写到目标路径，新逻辑下永远从 0 开始（因为探测的是 `target.filepart`）。
29. **新加枚举变体会让 UI 的 `match` 不穷尽**：`TransferOutcome::Skipped` 与
    `SftpEvent::UploadConflict` 都要在 `handle_event` / `render_row` 里补分支。
30. **弹窗被「误点」的假象**：连续两次截图都看到队列行是「已完成」且没有弹窗，
    以为弹窗没渲染。加了事件日志才看清：弹窗确实开了，3 秒后被鼠标恰好停在
    「安全覆盖」上的合成/真实点击解掉了。**验证弹窗类 UI 前先把光标挪开**
    （`CGWarpMouseCursorPosition`）。
31. **不要用合成 CGEvent 去点真实桌面的按钮**：`CGEvent.post` 会触发 macOS 的
    「正在尝试修改你的系统设置」TCC 弹窗，而且事件并不会落到应用上。需要「点一下
    按钮」的验证，改成 worker 层的 `ResolveUpload` 用例
    （`worker_resumes_when_user_picks_resume`）更可靠。
32. **演示模式加第二个钩子**：`MACSCP_DEMO_RESUME=1` 在 `demo::seed()` 里给
    `notes.md` 预置 6 字节 `.filepart`（本地文件 14 字节），弹窗才会走「可续传」分支，
    否则 `can_resume` 永远是 false、续传按钮永远是灰的。

## 第八轮：应用图标

用户要求「给可执行程序添加一个图标」。macOS 的规则和 Linux/Windows 完全不同，
所以拆成两条路，两条都做了：

- `assets/icon/macscp-icon.svg`：1024×1024 矢量源，圆角方块 + 上下双箭头。
  刻意不放双栏/服务器/文件夹 —— 16px 下会糊，而「⇅」能认出来。
- `scripts/make-icon.sh`：无头 Chrome 光栅化 → 1024 PNG → 10 档 iconset →
  `iconutil -c icns` → `assets/icon/AppIcon.icns`（992 KB）。
- `scripts/bundle.sh`：二进制 + icns + `Info.plist` + `PkgInfo` → `target/<profile>/macscp.app`，
  版本号从 `Cargo.toml` 现读，最后 ad-hoc `codesign` + `touch`。
- `src/ui/app_icon.rs`：`include_bytes!` 把 icns 嵌进二进制，启动后
  `NSApplication.setApplicationIconImage:` 设成 Dock 图标 —— 裸二进制（`cargo run`）
  没有 bundle，只能这么干。

### 新踩到的坑

33. **裸 Unix 可执行文件在 Finder 里永远不会有自己的图标**：不管往二进制里嵌什么，
    Finder 显示的都是系统给「Unix 可执行文件」的通用图。要 Finder 里好看只能包成
    `.app`（`Contents/Resources/*.icns` + `Info.plist` 的 `CFBundleIconFile`）。
    但 **Dock 图标可以在运行时改**，所以 `cargo run` 也能有图标。
34. **无头 Chrome 截 SVG 要 `--default-background-color=00000000`**，否则透明区域变白底，
    icns 里会带一圈白边。另外窗口按 512 CSS px + `--force-device-scale-factor=2`
    得到 1024 物理像素，比直接开 1024 窗口快得多（软件渲染，大窗口会卡几十秒）。
35. **`iconutil -c icns` 要求 iconset 里 10 个文件名一个不差**（1x/2x 各五档），
    缺一档直接报错，不是警告。
36. **`objc2` 的 `alloc` 来自 `AnyThread`，不是 `ClassType`**（0.6 起）。写
    `use objc2::ClassType as _;` 会报 "no associated function named `alloc`"，

## 17:30 「要点两次连接才能连上」→ 建连自动重试

现象：点「连接」第一次弹 `无法建立 SSH 连接：No route to host (os error 65)`，
再点一次就成功（截图里「已连接到服务器」和这条错误同时在）。

排查结论（**不是** app 状态机的问题）：

- 一次点击只发一条 `SftpCommand::Connect`，两次点击的配置完全一样（都是
  `root@192.168.146.7:22` + 空私钥路径），工具栏的 `Connecting` 守卫也挡住了重复点击
  → app 侧两条路径等价，差异只能在网络层。
- 本机 `ifconfig`：**两张网卡共用 192.168.146.0/24** —— `en6` 192.168.146.2（虚拟机桥接）
  和 `en0` 192.168.146.4；`netstat -rn` 里同一个 /24 有两条 link 路由（一条 IFSCOPE）。
  目标 `.7` 是 VMware 虚拟机（MAC `0:c:29:…`），两张网卡的 ARP 表里都有它。
- 这就是经典的「ARP 缓存过期后第一个 SYN 被内核发到失效网卡上 → `connect(2)` 直接
  返回 `EHOSTUNREACH`」。失败的 SYN 顺带触发了 ARP 重新解析，所以紧接着重试必通。
  `nc` 探测：`.7:22` 通；同网段未使用地址 `.222` 是 **timeout**（不是 EHOSTUNREACH）
  —— 说明 EHOSTUNREACH 只来自「路由/ARP 明确不可达」这条快路径，重试成本极低。

改动（`src/sftp/session.rs`）：

- `is_transient_connect_error`：`HostUnreachable` / `NetworkUnreachable` /
  `ConnectionReset` / `ConnectionAborted` / `HUP` / `Disconnect` 视为瞬时。
  **超时不重试**（用户已经等了 20s，再叠两次只会让结论更晚）、`ConnectionRefused`
  和认证失败也不重试。
- `connect_with_retries`：三次机会，间隔 400ms / 1200ms（数组长度绑
  `CONNECT_ATTEMPTS`，改次数忘了改等待会编译不过）。只包 TCP + 版本交换 + KEX
  这一段，认证和 SFTP 握手不重试。失败时把「最后一次错误 + 试了几次」一起返回。
- `explain_connect_error`：把 `No route to host (os error 65)` 翻成
  「主机不可达（No route to host）：host:port。检查主机是否在线、与本机是否在同一网段」，
  重试过就补「（已自动重试 3 次）」。`ConnectionRefused` / `TimedOut` / `ConnectionReset`
  各有对应文案。

### 踩到的坑

46. **`thiserror` 的 `#[error(transparent)]` 会让 `source()` 透传内层的 source**，
    `russh::Error::IO(io)` 因此拿不到 `io::Error` 本身 —— 想判 `ErrorKind` 只能
    `match russh::Error::IO(io)` 直接匹配枚举，别指望 anyhow 的错误链能 downcast 出来。
47. **不要在 `connect` 里用 `unwrap_or_else` 把超时压成 `Elapsed`**：`client::connect`
    返回 `Result<_, H::Error>`，`timeout` 外面再包一层是 `Result<Result<..>, Elapsed>`，
    直接把 `Elapsed` 映射成 `russh::Error::ConnectionTimeout` 最省事（`explain` 认得它）。
48. 沙箱里 `nc -z -G N` 的 `-G` 是连接超时；对**未使用**的同网段地址是 timeout、
    对**明确不可达**才是 "No route to host" —— 用这个区分「重试有用」和「重试没用」。

验证：`cargo test --bin macscp` 53 passed / 1 ignored（新增 5 条：瞬时/确定性错误分类、

`root@192.168.146.7` 建连 → `home=/root`，104ms 一次成功（验证完已删除该用例）。

## 18:15 整目录上传（上传文件夹）

需求：本地右键目录 / 从 Finder 拖目录 → 整棵递归传到当前远端目录。

### 协议与网络层

- `SftpCommand::UploadDir { id, local, remote, on_existing }`：**一条指令 = 队列一行**。
  500 个文件不会变成 500 行，取消也只需一个 `AtomicBool`。
- `ExistingPolicy { Overwrite, Skip }`：同名文件策略整批问一次（逐个弹窗在几百个文件时没法用）。
  和 `UploadDecision`（单文件：续传/覆盖/跳过）分开，两个概念别混。
- 新增 `src/sftp/local_tree.rs`：纯 `std::fs` 扫树，返回 `LocalTree { dirs(父在前), files, total_bytes, skipped }`。
  规则：符号链接**跳过**（环形链接会绕圈、也会传出根目录外）、隐藏文件**照传**
  （「显示隐藏文件」只是渲染开关，漏掉 `.env` 是最坏的安静）、空目录也要记（远端结构要对得上）。
  显式栈遍历，不递归（几十层深的 node_modules 不该打穿栈）。
- `transfer.rs` 重构：抽出 `upload_file`（探针 → `.filepart` → 原子替换），单文件和整批共用；
  进度出口抽象成 `UploadSink`（`RowSink` 原样映射一行，`BatchSink` 用 `base + 本文件已写` 折算整批）。
  `BatchSink.last` 让「文件失败」时进度不倒退 —— 否则下一个文件从 base 重来，进度条当场往回跳。
- `ensure_dir`：`create_dir` 失败后 `stat` 一次，是目录就当成功（mkdir -p 语义）。
  **别猜错误码** —— 各家服务器「目录已存在」返回的 code 不一样。
- 单个文件失败不中断整批，最后 `Failed` 只带首个错误 + 失败个数（逐个放弃更让人恼火）。
- 扫树用 `spawn_blocking`：读几千个目录不能占 runtime 工作线程。

### UI

- `menu_spec`：本地目录从「置灰」改成可点，文案 `上传文件夹到当前远程目录`（文件仍是「上传到…」）。
- `Workspace::confirm_upload_dirs`：`open_dialog` + 两个按钮（跳过同名 / 覆盖同名），
  按钮里 `weak.update(cx, |ws, cx| ws.start_folder_uploads(dirs, policy, cx))` —— 不用事件订阅，
  也不用在对话框里持有 `TransferId`。
- 拖放：`split_dropped` 仍拆文件/目录，但目录不再「跳过并提示」，而是收集起来**一次**问策略
  （一次拖三个文件夹只弹一个框）。
- 队列行名字用 `name/`（结尾斜杠），一眼看出是文件夹；总量 0 入队，`TransferStarted` 补上。
- 演示钩子 `MACSCP_DEMO_FOLDER=1`：连上后自动传一棵预置小树，不用手动操作就能看到效果。

### 假服务器（testserver.rs）大改

原来只有 `opendir`（只认 HOME 和 `/`）/`readdir`（固定 fixture）/`open`/`read`/`write`/`stat`/
`setstat`/`remove`/`rename`，**没有 mkdir**，目录也不在 VFS 里。现在：

- 目录也是 VFS 里的一条记录（`DIR_MODE = 0o040_755`，靠类型位区分），`mkdir` / `rmdir` 都实现；
- `opendir` 接受任何存在的目录，`readdir` 对子目录从 VFS 按父路径取直接子项；
  **HOME 仍然走固定 fixture + EXTRA_ENTRIES**（否则并行跑的传输用例会把「正好 5 项」的断言弄挂）；
- `open(WRITE)` 现在要求父目录存在 —— 整目录上传漏建某一层会立刻暴露，而不是悄悄造出一条怪路径；
- `remove` 拒绝目录（unlink 语义），删目录走 `rmdir`（非空返回 Failure）。

### 19:05 修掉假服务器的一个并发 bug（整目录下载「随机少文件」的真凶）

复跑演示时出现「下载 0 个文件 / 0 个子目录」，而同一份代码刚才还成功过 —— 典型的竞态。

定位过程（值得记，因为**先怀疑错了对象**）：
1. 先怀疑刚改的 `remote_tree` 深度重构 → 加日志，发现 `list_dir` 返回 0 项，说明**根本没走到** absorb。
2. 再怀疑 demo 的预置数据没落盘 → 探针 `vfs_read("/home/tester/demo-pkg/a.txt")` 返回 `Some(14)`，数据在。
3. 于是问题在服务端 `readdir` → `children_of` 返回空。第 4 次跑又正常了 → 是竞态。

真凶：`TestSftp { drained: bool }` —— 假服务器用**一个裸 bool** 记「这个目录读完了没」。
一个连接上同时发生两次 `read_dir`（UI 刷新家目录 + 整目录下载扫树）时：
`opendir(HOME)` → `drained=false`；`opendir(demo-pkg)` → `drained=false`；
`readdir(HOME)` → 吐数据并置 `drained=true`；`readdir(demo-pkg)` → 看到 true，**回 EOF**，
客户端把 EOF 当成「读完了」，于是拿到空列表 —— 没有报错，只是安静地少文件。

58. **SFTP 的「读到哪儿了」必须绑在句柄上，不能绑在路径/会话上**。真实服务器每次
    `opendir` 给新句柄；假服务器也得照做（`open_dirs: HashMap<String, DirCursor>` +
    `next_dir_handle`，句柄 `dir-N`）。`concurrent_read_dirs_do_not_share_the_eof_flag`
    钉住它：交替读两个目录，第二个必须拿到自己的内容。
59. **`russh_sftp::server::Handler` 没有 `closedir`**，客户端也不发 CLOSE → 游标只能自己回收
    （攒到 `MAX_OPEN_DIRS = 1024` 整表清掉，句柄递增，最早的早就读完了）。
60. **`grep` 在 Bash 工具里对中文 pattern 会静默返回空**（退出码 1，不是匹配失败）。查中文
    一定要用 Grep 工具 —— 之前用 `grep "个用例"` 得出「README 里没有这句话」的错误结论。
61. **远端扫描加 64 层封顶**：`local_tree` 有 `symlink_metadata` 兜底，远端只能靠深度封顶 ——
    某些服务器把「指向目录的符号链接」报成目录，`a -> ..` 会让扫描无限往下。

补的用例：`absorb_stops_at_the_depth_cap`、`download_dir_honours_a_preset_cancel_flag`、
`download_dir_reports_a_missing_remote_root`、`concurrent_read_dirs_do_not_share_the_eof_flag`。

验证：`cargo test` **77 passed / 1 ignored**；clippy 自有代码 0 警告；演示连跑 3 次
都稳定 `3 个文件 / 3 个子目录 / 262170 字节`；`./scripts/build.sh` 已重建 dist/。
